# EdgeSphere Feature Provenance & Disclosure Manifest

To uphold engineering integrity during evaluation, this document outlines what constitutes genuinely functional software logic versus simulated prototypes in EdgeSphere.

---

## 1. Truly Implemented Software Logic

The following capabilities are genuine, executed software components:

| Feature Area | Genuine Logic Implemented | Verification Method |
|---|---|---|
| **Frontend Architecture** | Fully functional React 19 + TypeScript Single Page Application with routing, navigation state, and sub-pages. | Rendered in browser, verified by 84 automated Vitest tests. |
| **Design System** | Complete CSS Custom Property (Design Token) technical editorial system with unified spacing, typography, borders, and light surfaces. | `tokens.css` + `components.css` audited and verified. |
| **FedAvg Parameter Aggregator** | Mathematical federated averaging engine: $\mathbf{w}_{\text{global}} = \sum (n_k / N) \mathbf{w}_k$. Computes sample-weighted vectors across clients, calculates weighted loss, and updates parameter records. | Tested in Vitest with unequal weights, single clients, and reset conditions. |
| **Hardware-Aware Scheduler** | Evaluates node sensor compatibility, physical bus access, and sampling rates before proposing workload migrations. | Rejects Nano 33 BLE for motor ADXL345 workload; routes to Gateway CPU. Tested with Vitest. |
| **State Persistence** | Versioned browser `localStorage` schema (`v1`) that serializes fleet configurations, custom node registrations, and incidents. Gracefully handles corrupted JSON. | Unit tested with invalid payloads and verified across browser reloads. |
| **Data Export** | Generates authentic RFC 4180 CSV blobs and triggers browser file downloads for audit tables and benchmark fixtures. | Verified via DOM download trigger and file inspection. |

## 2. Simulated Edge AI Logic (Truthfully Disclosed)

The following components represent simulated edge behaviors designed to model platform operation prior to physical hardware availability:

| Feature Area | Simulated Behavior | Disclosure in UI |
|---|---|---|
| **Sensor Telemetry Feeds** | Accelerometer, microphone, and environmental values are generated via deterministic sinusoidal equations with pink noise in `telemetrySimulator.ts`. | Banner prominently states: *"Simulated Edge AI Fleet: Telemetry values, FFT features, and INT8 scores are generated by the local simulator. Hardware is currently unattached."* |
| **TinyML Inference Models** | INT8 prediction scores, anomaly scores, and classification outputs are synthesized via deterministic rule-based algorithms based on current simulated signals. | Marked as `Simulated Live` and disclosed in inspector modals. |
| **Client Local Training** | Sensor nodes perform synthetic gradient descent steps using deterministic mathematical offsets rather than physical on-chip backpropagation. | Labeled as `UI Federated Learning Prototype` with simulated delta indicators. |
| **Energy & Latency Metrics** | Inference execution latencies ($8.8\text{ ms}$, $1.8\text{ ms}$) and microjoule energy dissipation ($42\ \mu\text{J}$, $280\ \mu\text{J}$) are simulated estimations derived from datasheets. | Explicitly labeled as `est. ms` and `est. µJ`. |
| **Engine Benchmark Tables** | TensorFlow Lite Micro, Edge Impulse EON, and ARM CMSIS-NN benchmarks are configured fixtures based on published documentation. | Classification column explicitly labels all rows as `Configured Demo Fixture`. |

---

## 3. Explicitly Unimplemented Capabilities

To prevent misconceptions, the following hardware dependencies are **NOT** claimed:

1. **Physical Microcontroller Connection**: No physical Arduino Nano 33 BLE or ESP32 boards are attached via USB, UART, or BLE.
2. **Physical Over-The-Air (OTA) Flashing**: Firmware binaries are not flashed onto microcontrollers.
3. **Real MQTT Broker / Cloud Infrastructure**: Operates strictly local-first; no external AWS, GCP, or public MQTT brokers are required or connected.
